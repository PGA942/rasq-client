# 法務面と設計の変更点(2026-09-17)

出どころは Obsidian の「法務面と設計周りの変わる点/その1.md」(オープンテストの法務相談の記録)。
相談の中で案が何度か変わっているので、ここには**最後に話された版**と、その後のユーザー決定だけを載せる。
法的な助言そのものではない。届出の要否と会話ログの扱いは、実際の仕様で窓口に確認する。

## 1. ユーザー決定(相談の後に確定したもの)

| 項目 | 決定 |
|---|---|
| テスト終了後のアカウント | **そのまま正式版へ引き継ぐ**。運営による一括破棄はしない。削除は本人の操作で、サーバー上のデータをすべて消す(ストアのアカウント削除要件をこれで満たす) |
| サーバー | 枚方 / 神戸の回線は商用利用できないと判明。**さくらのクラウドをメイン**にする(Central とエッジ) |
| judge(審査と発信傾向) | さくらのメモリでは LLM が動かない見込み。**judge は運営者の PC で動かす**。web コンソールからデータを受け取り、しきい値(emotion8 のスコアや特定の語)で半自動に処理する。同じ条件で 1000〜10000 件をまとめて許容し、判定が怪しいものだけ人が処置する |
| RASQ アカウントの登録 | 登録のときに「アカウントバンドルを置き換えるか」と利用規約の FOW を出す(D-241) |

## 2. 相談で固まった仕様(最新版)

### 年齢
- 利用は 13 歳以上。18 歳未満は保護者の同意。連携する SNS の条件が高ければそちらにも従う。
- 学習へのデータ提供は 16 歳以上。16〜17 歳は保護者の同意つき。
- 公開プロフィールの誕生日、RASQ 内部の年齢の申告、学習の同意、保護者の同意は別々に記録する。プロフィールを書き換えても同意の履歴は変わらない。
- 2026 年 7 月公布の改正個人情報保護法(16 歳未満の同意は法定代理人)は施行準備中。公開時に施行状況を確認する。

### 学習へのデータ提供
- RASQ の利用同意とは独立。既定は「提供しない」。断っても通常の機能は使える。
- 対象は、同意した本人が書いた公開の投稿と、本人が付けた関連判定の正解ラベル。
- 対象外は、DM、限定公開の投稿、AsTell の会話、他人の引用本文や転載画像。2 投稿を結ぶラベルは両方が条件を満たすときだけ。
- 目的はリレーショナル TL の関連判定・分類・順位付けの改善だけ。RAi の汎用学習や感情・人物評価には使わない。AsTell 向けの学習(感情分析や入室判定)は別の同意にする。
- 学習したモデルは端末へ配布する。元データは配布しない。どのデータをどの版に使ったかを記録する。
- 「AI 学習禁止」の判定 bot は補助。検出しなかったことを許可とはみなさない。同意後に見つけたら収集を止めて本人に確認する。
- マスキングや PQC 暗号化をしても、SNS アカウントとひも付く間は個人情報として管理する。「匿名化済み」とは説明しない。

### 保存期間
| 対象 | 運用 |
|---|---|
| 取り込んだ未加工データ | マスキングと確認のあと短期間で削除 |
| 学習用データ・正解ラベル | 各データの取得から最大 5 年。再学習で取得日を更新しない |
| SNS アカウントとの対応表 | 本文と分離し、除外の対応に必要な最小限 |
| 同意・撤回・削除の記録 | 証明と問い合わせ対応のため、別の保存期限 |
| バックアップ | 削除が反映されるまでの最大期間を決める。復元しても削除を再適用する |

### 撤回と削除
- 撤回はメジャー更新(3 か月〜2 年)から独立した処理にする。
  - 受付の直後: 新しい収集と学習への投入を停止。
  - 30 日以内(運用目標): 学習データ、評価用データ、派生データを削除。
  - 既存モデル: 次の通常更新で、除外後のデータから作り直す。旧モデルへの追加学習では「除外した」と言えない。個人情報の再現などが分かれば更新を待たず配布停止・差し替え。
  - 端末に渡った旧モデルの完全回収は約束しない。
- **アカウント削除は、学習の撤回と提供済みデータの削除も同時に始める**。「別に撤回しない限り残る」はストアの要件と衝突する。ベータ版であることは免除の理由にならない。
- 学習の撤回だけを、アカウントを残したまま行える。
- 確認ページは本人確認のあと自分の記録だけを見せる。SNS サーバーの終了に備えて、提供時に撤回用のコードを発行する。Keybase は任意の補助。

### AsTell
- WebRTC でサーバーが媒介する。**公開前に電気通信事業の届出の要否を確認する**(近畿総合通信局。接続図、公開 / 限定ルームの違い、中継の有無、広告収益、保存するログを添える)。
- 共有は、公開できる投稿だけ本文ごと配る。限定公開 / DM / ローカル限定 / 公開範囲が不明は本文を拒否し、リンクだけ通す(D-242 / S-016 で実装済み)。
- CW とセンシティブ指定は独立した情報として持つ。
- 運用ログに会話の本文、音声、認証トークンを入れない。
- DM は UI に出すだけでは「媒介」にならない。端末から SNS へ直接送る今の構成を保つ。

### 広告
- モバイルは AdMob。公開版を開発者が確認する端末もテスト広告の設定にする。オープンテスト用と開発用でブランチを分ける。
- **デスクトップ(macOS / Linux)の AdSense WebView 埋め込みは採用しない**(デスクトップアプリ経由の配信は規約で制限。Central 上のページを読み込む形でも解消しない)。初回テストのデスクトップ版は広告なし、サーバー計算量に上限。

### 文書
オープンテスト利用規約 / プライバシーポリシー / 学習へのデータ提供の説明と同意 / AsTell 利用時の説明の 4 つに分ける。
プラグインの規約画面(`terms_sheet.dart`、空なら素通し)は RASQ 本体と学習の同意には使わない。
「テストなので一切責任を負わない」という全面免責は書かない(消費者契約法で無効になる条項がある)。
「すべて国内で処理する」とは書かない(Cloudflare と Google を使う)。

## 4. judge の半自動処理(J-006、ユーザー決定 2026-09-17)

運営は当面 1 人(将来も数人)。人の手は誤 BAN の解除に回したいので、通報の処理は「ほとんど何も考えなくても設定できる」形にする。
judge は運営者の PC で動かし、Central(さくら)の管理 API を引く。Central から judge へは繋がない。

1. 通報された人の、通報の前後の発信を取る(Central `GET /admin/reports/{id}/context`)。
2. 埋め込み・emotion8・語の**遷移**を取る。時間の経過でヒートアップしたのか、落ち着いたのかで判断が変わり得るため。
3. 似た状況を Louvain でまとめ、まとまりの中を深刻さの順に並べる。
4. 一定の間隔で選んだ人だけを LLM に掛け、どんな遷移がセーフ / アウトかを判定する。ここで**承認 ①**。
5. 間に挟まれた人は、両側のサンプルの判定の割合から決める。割れていれば保留にして人が見る。
6. **承認 ②** で適用する。問題なしはまとめて却下、アウトは近いサンプルの処置を写す。恒久凍結は自動では掛けない。

補助として、語ごとの危なさ(その語を含む状況のうちアウトになった割合)と、まとまりごとの emotion8 の集計を出す。
設定はすべて既定値で動く。LLM に掛ける件数は件数の平方根の 2 倍(10000 件で 200)。

将来: 強めの MoE モデルを AWS のワーカーで回し、サンプルの判定と解除申請の下読みを軽くする。
入室時の発言の検閲(`screen_text`)は、当面サーバー内の語彙だけで続ける。
