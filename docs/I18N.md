# 表示の言語(i18n)の進め方 (D-484)

今は**日本語だけ**。仕組みを先に入れ、文言の抽出は領域ごとに何回にも分けて進める。英語などを足すときは、
**訳のファイルを足すだけ**で済むようにしてある(コードは触らない)。

製品全体の約束(アプリ・同梱プラグイン・Web のコンソール・サーバーのメール / 通知で共通):

| 何を | どうする |
| --- | --- |
| アプリの表示の言語 | 設定 → アプリの外観 → **言語**: 「システムに合わせる」(既定)か、対応する言語の一覧(訳のファイルから作る)。端末に保存(KV `appearance.language.v1` の `locale`)。端末の言語に対応していなければ日本語 |
| Central / ORGATE への要求 | 全部に `Accept-Language: <表示の言語の BCP-47>`(`OrgateClient` が付ける。Central への口も同じクラス) |
| RASQ アカウントの言語 | ログインしているあいだ、表示の言語が変わったとき / ログインしたときに ORGATE へ `PATCH /api/v1/me {"locale": "<BCP-47>"}`(`lib/l10n/locale_sync.dart`)。古い ORGATE の 400 などは黙って諦める |
| プラグイン | 毎回の `call` の args に、ホストの予約の項目 `"locale": "<BCP-47>"` を載せる(契約 v0.24、rasq-sdk-sample PROTOCOL.md §4.6)。`packages/plugin_runtime/lib/src/host_call_args.dart` の 1 か所(同期 / 非同期のコントローラの `invoke` = SNS の `sns.*`・匿名ワーカーの `sns.settingsPages`・`plugin.manifest`・スロットの call 全部)。args に同じ名前があってもホストの値で上書き。起動時の init は無い(ABI v1)。`page.open` の `contract` は `"0.24"`(v0.25 から `"0.25"`、D-500) |
| プラグインの文を持つところ | `sns.settingsPages`(`WasmSnsPlugin`)・`sns.actions` / `sns.timelines`(`WasmSnsSession`、次の TL 取得の前)・`tl.timelines`(`customTimelinesProvider`)・設定ページの provider は、表示の言語が変わったら読み直す |
| マニフェストの文 | `defaultLocale` / `locales.<tag>.{name, description, termsOfService, pageTitle, actions.<id>.label, assets.<id>.label}` を、タグ → 親のタグ → 素の欄の順に引く(`ManifestLocales`、`PluginManifest` / `SlotManifest` の `name` などは表示の言語の値を返す。素の値は `baseName` など) |

## ファイルの置き場

```
l10n.yaml                              gen-l10n の設定(アプリ)
lib/l10n/parts/<領域>.<言語>.arb        ← 文言はここに書く(領域ごとの部品)
lib/l10n/app_<言語>.arb                 tool/l10n_merge.dart が部品からまとめる(手で直さない)
lib/l10n/gen/                          flutter gen-l10n の生成物(コミットする)
lib/l10n/l10n.dart                     context.l10n / appL10n
lib/l10n/ui_locale.dart                表示の言語の決め方(設定・端末の言語・対応していなければ ja)
lib/l10n/locale_sync.dart              ORGATE への PATCH /me
lib/l10n/asset_strings.dart            設定の静的なページの文言の参照(`@l10n:<キー>`)を引く (D-535)。表は asset_strings.g.dart(生成物)
packages/rasq_design/l10n.yaml         部品(rasq_design)の文言。仕組みはアプリと同じ
packages/rasq_design/lib/l10n/parts/   (キーは design…)。context.designL10n / rasqDesignL10n / RasqDateFormat
packages/<部品>/l10n_dart.yaml         Flutter に依らない部品(rasq_models / rasq_plugin_api / sns_misskey)の文言 (D-533)
packages/<部品>/lib/l10n/parts/        (キーは models… / pluginApi… / misskey…)。生成物は lib/l10n/gen(素の Dart)
tool/l10n_merge.dart                   部品 → まとめた ARB(--check で食い違いだけ見る)。l10n_dart.yaml の部品は素の Dart の文言のクラスも作る
tool/l10n_audit.dart                   残っている日本語のリテラルを数える
```

生成物(`lib/l10n/gen`)をコミットするのは、Flutter 3.29 から synthetic package(`package:flutter_gen`)が無くなり、
ソースの中に出す形だけになったため。`pubspec.yaml` の `flutter: generate: true` はそのまま(`flutter run` / `test` の
ときにも作り直される)。CI の `flutter` ジョブは、部品とまとめた ARB・生成物がコミット済みのものと同じかを見る。

## 文言を足す / 抽出する手順

1. 領域の部品を決める。`lib/l10n/parts/<領域>.ja.arb`(領域は小文字と `_`)。例: `settings.ja.arb`(設定の第一階層)、
   `settings_security.ja.arb`(アカウントとセキュリティ)、`shell.ja.arb`。**並べて進める抽出は部品を分ける**
   (同じ部品を 2 本で触らない)。
2. キーは**部品の名前の lowerCamelCase で始める**(`settings_security.ja.arb` → `settingsSecurity…`)。
   tool/l10n_merge.dart が確かめる。続きは画面の中の役目が分かる名前にする(`…Title` / `…Subtitle` / `…Caption` /
   `…Detail`(開発者モードの詳しい説明)/ `…Button` / `…Error…` / `…Semantics`)。文言そのものをローマ字にしない。
3. 文言は**変えない**(抽出は置き換えだけ。言い回しを直すなら別の変更で)。
4. 変数の入る文言はプレースホルダ、数の入る文言は ICU の plural にする(日本語は `other` だけでよい。英語を足すときに
   `one` を足す):

   ```json
   "settingsSecurityDevicesCount": "{count, plural, other{{count} 台の端末}}",
   "@settingsSecurityDevicesCount": {"placeholders": {"count": {"type": "int"}}},
   "shellAccountSwitched": "{name} に切り替えました",
   "@shellAccountSwitched": {"placeholders": {"name": {"type": "String"}}}
   ```

   `@キー` の `description` には、訳す人に要る説明(どこに出るか、プレースホルダの中身)を書く。
5. コードは `context.l10n.<キー>`(`import '../../l10n/l10n.dart';`)。`BuildContext` の無いところ(enum の名前・
   例外の文・`const` の表)は `appL10n.<キー>`(いまの表示の言語)。`const` の表は「`AppLocalizations` を受けて表を返す
   関数」にする(例: `settingsSectionsOf(l)`)。部品(rasq_design)の中は `context.designL10n` / `rasqDesignL10n`。
6. 日付は `RasqDateFormat`(`monthDay` = `8月31日` / `yearMonth` = `2017年2月` / `yearMonthDay` / `time`)。
   `'${d.month}月${d.day}日'` のような組み立ては使わない。
7. `dart run tool/l10n_merge.dart && flutter gen-l10n`(rasq_design の文言を触ったら `(cd packages/rasq_design && flutter gen-l10n)` も)
   を回し、生成物ごとコミットする。
8. `dart run tool/l10n_audit.dart` で残りを数える(`--files` でファイルごと、`--list lib/shell` で 1 件ずつ)。

訳さないもの(検索の語彙の日本語、ログ、開発用の画面の固定の文など)は抽出しない。数えたくなければ行末に
`// l10n-ignore` を付ける。ログ(`debugPrint` など)とコメントは最初から数えない。

### テスト

`context.l10n` は、`AppLocalizations.delegate` の無い画面(部品だけを `MaterialApp` に置くテスト)でも日本語を返す。
文言は変えないので、日本語の文字を探す既存のテストはそのまま通る。新しいテストで文言を探すときも日本語の文字で探してよい
(キーの名前より読みやすい)。

## 設定の静的なページ(assets/settings/*.rrl.json)(D-535)

設定の第二階層の多くは、wasm の要らない静的な RRL のアセット(`assets/settings/<area>.rrl.json`)。中の文は 2 種類に分けて扱う。

- **画面のページ**(`doc` を持たないもの。外観・プラグイン・ASTell・リソースなど 29 枚): JSON に文字列を直接書かず、
  `"@l10n:<キー>"` を書く。文言は ARB の部品 `lib/l10n/parts/settings_pages.<言語>.arb`(キーは `settingsPages<area><役目>`)。
  プレースホルダの要る文は `{"$l10n": "<キー>", "args": {"<名前>": <値>}}`(波かっこを含む例の文など)。読み込んだあと
  `resolveAssetStrings`(`lib/l10n/asset_strings.dart`)が表示の言語の文言に置き換える(設定のページの provider と設定の検索の
  両方。言語が変われば読み直す)。キー → 文言の表 `lib/l10n/asset_strings.g.dart` は tool/l10n_merge.dart が部品 `settings_pages*`
  から作る(`--check` も見る)。文言の元は ARB だけで、訳す道具もほかの画面と同じ。test/settings_pages_l10n_test.dart が、
  画面のページに日本語が直接残っていないこと・参照が全部引けること・使わないキーが無いことを確かめる。
  ページを足す / 直すときは、文言を部品に足して JSON にはキーを書く。
- **文書のページ**(`doc` を持つもの。規約・プライバシーポリシー・学習・ストアなど 10 枚): 文書は**文書ごと訳す**(言い回しを
  法務の文書として確かめ、版と `bodySha256` も言語ごとに違う)ので ARB には入れない。訳した文書は言語ごとのファイル
  `assets/settings/<言語>/<area>.rrl.json`(`en` / `en-US` など)に置く。読み込みは表示の言語のタグ → 言語だけ → 日本語の元
  (`assets/settings/<area>.rrl.json`)の順(`settingsPageAssetPaths`)。いまは日本語だけ。訳を足すときに要ること:
  ①tool/legal/build_legal.py を言語ごとの Markdown(`assets/legal/<言語>/…`)から `assets/settings/<言語>/` へ書けるように
  する、②pubspec.yaml の `assets:` に `assets/settings/<言語>/` を足す、③承諾の記録(`legal_docs.g.dart` の版 / sha256、
  Central の承諾の版)をどの言語の文書に同意したかまで持つようにする(いまは日本語の文書の sha256 だけ)。

## 部品(packages/*)の文言 (D-533 / D-534)

部品は**自分の文言を自分の中に持つ**(アプリの ARB に置いて渡し込む形はとらない。文言の元は 1 か所、訳す道具は ARB のまま)。

| 部品 | 仕組み | 引き方 |
| --- | --- | --- |
| rasq_design(Flutter) | `l10n.yaml` + `flutter gen-l10n` → `RasqDesignLocalizations`(D-484) | `context.designL10n` / `rasqDesignL10n` |
| rasq_overlay / rrl_renderer / plugin_runtime(Flutter、rasq_design に依る) | 自分の ARB は持たず、**rasq_design の部品**(`design_overlay.ja.arb` / `design_rrl.ja.arb` など、キーは `designOverlay…` / `designRrl…`)に置く(D-534)。どれも部品の画面の決まり文句で、rasq_design に依れば足りる | `context.designL10n` / `rasqDesignL10n` |
| rasq_models / rasq_plugin_api / sns_misskey(Flutter に依らない) | `l10n_dart.yaml` + `lib/l10n/parts/*.<言語>.arb` → **tool/l10n_merge.dart が素の Dart のクラス**(`RasqModelsLocalizations` / `RasqPluginApiLocalizations` / `SnsMisskeyLocalizations`)を `lib/l10n/gen` に作る | `rasqModelsL10n` / `rasqPluginApiL10n` / `snsMisskeyL10n`(= `lookup…(RasqUiLocale.tag)`) |

Flutter に依らない部品は `flutter gen-l10n` を使えない(生成物が `package:flutter` を要る)。部品を Flutter に依らせると、
素の Dart で動かすもの(`packages/sns_misskey/example/probe.dart` など)が動かなくなるので、生成だけを tool/l10n_merge.dart で行う:

- 設定は `l10n_dart.yaml`(書き方は l10n.yaml と同じ: `arb-dir` / `template-arb-file` / `output-dir` / `output-localization-file` /
  `output-class`)。名前を変えてあるのは、`flutter gen-l10n` がこの部品で動かないようにするため。
- 生成物 = 文言の抽象クラス(キーごとの getter / メソッド、`description` が doc コメント)、言語ごとのクラス(訳の無いキーは
  テンプレートの言語の文言に倒す)、`lookup<クラス>(タグ)`(タグ → 言語だけ → テンプレートの言語)。
- ICU は gen-l10n と同じ書き方の範囲(`{名前}`・`plural`・`select`)。plural / select を使う部品は `package:intl` に依る
  (いまは sns_misskey だけ)。表示の言語は rasq_models の `RasqUiLocale.tag`(アプリが設定する)。
- `dart run tool/l10n_merge.dart` が生成し、`--check` が生成物も見る(CI は `packages/*/lib/l10n` の食い違いも見る)。
- 言語を足すとき: その部品の `lib/l10n/parts/<領域>.<言語>.arb` を置いて `dart run tool/l10n_merge.dart`。

Misskey のアダプター(sns_misskey)は SNS のプラグインの Dart 版なので、WASM のプラグインと同じく文言を自分で持ち、表示の言語は
ホストから受け取る(WASM のプラグインは `call` の `locale`、Dart 版は `RasqUiLocale.tag`)。設定のページ(`sns.settingsPages`)と
アクションの名前は読むたびに表示の言語で作る。同梱のプラグインのマニフェストの名前・説明(`Misskey Plugin` /
「Misskeyに接続するためのプラグイン。」/「mixi2 (サンプル)」)はプラグインの中身として `// l10n-ignore` で残した。訳すときは
マニフェストの `locales`(ほかのプラグインと同じ)に書く。

## RAi の指示の文 (D-492)

RAi が LLM / 検索に渡す文(system の指示・差し込む見出し・関数の一覧・Brave Answers への添え書き)は、表示の言語ごとに
**別の表**で持つ。RAi はその言語で考え、その言語で答える。

- 置き場: `lib/features/rai/prompts/rai_prompts.dart`(`RaiPrompts` の約束と、言語 → 表の `raiPromptCatalogs`)、
  `rai_prompts_<言語>.dart`(言語ごとの実装。いまは `RaiPromptsJa` だけ)。選ぶのは `raiPrompts`
  (= `RasqUiLocale.tag` → 言語の部分 → 日本語)。コードは `raiPrompts.assistantSystem` などで引く。
- ARB の部品に入れないわけ: 指示の文は長く、何行にもまたがり、`{…}` を地の文に含む(`[[call:<関数>|引数=値|…]]`)ので
  ICU の書式とぶつかる。訳す人は画面の文言ではなく「モデルへの指示」として訳す(長さの上限・箇条書きの書式などの
  約束を崩さない)。表は Dart のクラスなので、欠けた文はコンパイルで分かる。
- **言語に依らず同じにするもの**(書式の約束): `[[instruction:<id>|…]]` / `[[call:…]]` の書き方、関数の名前と引数の名前
  (`posts.fetch(kind=home|search, …)` の英字の部分)、関数の一覧の行の「`名前(…)・名前(…): 説明`」の形と行の数
  (`raiFunctionUsageFor` が `: ` と `・` で読む)。値の説明(`語` / `@名前` など)は訳してよい。
- 答えの言語を指定する文(「日本語で答えて」)は、その言語の名前(`languageName`)を含める。
- test/rai_prompts_test.dart が、全部の表について上の約束を確かめ、日本語の表が D-490 の時点の文と 1 バイトも違わないことを確かめる。
- `tool/l10n_audit.dart` は `…/prompts/` の下を数えない(言語ごとの訳そのものなので)。
- 関数の結果の文(`RaiFunctionResult.text`)は画面の文言と同じく ARB の部品(`rai_functions.ja.arb`)から出る。

言語を足すときは `rai_prompts_<言語>.dart` に `RaiPrompts` を実装し、`raiPromptCatalogs` に足す。

### 言語ごとの照合のデータ(訳ではなく、言語ごとに作り足すもの)

RAi には、利用者の発言を読むための**日本語の照合のデータ**が `// l10n-ignore` 付きで残っている。これは訳す文ではないので
ARB にも指示の表にも入れない。言語を足すときは、その言語の言い回しに合わせて**別に作り足す**(今はどれも日本語の発言を前提に
している。ほかの言語の発言では当たらず、聞き返す / 関数の既定に倒れるだけで壊れはしない):

- `rai_reference.dart` の `stemJa` などの語幹の切り出し(「したい」「するには」などの語尾)。
- `rai_automation.dart` の任せる言い回し(`_entrustedRe`)、入力を質問から抜く正規表現(`raiExtractInput` のフィード / ワード /
  本文 / 取り込み先)、入力のラベル(`フィード` / `RASQ リスト` / `ワード` / `本文` / `取り込み先` とその値。キーとして使う)。
- `rai_providers.dart` の複合の質問の判定(「してから」「したら」など)。
- `rai_functions.dart` の真偽の語(`オン` / `はい` / `オフ` / `いいえ`)。
- `features/relational/relational_engine.dart` の特徴語の抜き出し(全角の `＃`、カタカナ / 漢字の連なり)と、反応表現の語彙
  (`_reactionLexicon`:「それな」「わかる」など。関連 TL で短い相づちの投稿を前の会話に寄せる)。D-528。
- `features/clips/virtual_index.dart` の目次の語の候補(漢字とカタカナの混ざった語)。D-529。
- `features/learning/contribution.dart` の「AI の学習に使わないで」の言い回しの表(`_optOutPhrases`。Central の規則と同じものを
  両方で持つ。言語を足すときは両方に足す)。D-532。

## 言語を足すとき(例: 英語)

1. 各部品の横に訳を置く: `lib/l10n/parts/<領域>.en.arb`、`packages/rasq_design/lib/l10n/parts/design.en.arb`。
   キーはテンプレート(ja)にあるものだけ。欠けたキーは日本語で出る(gen-l10n が倒す)。`languageSelfName` には
   その言語での名前(`English`)を入れる — 設定の言語の一覧はこれを出す。
2. `dart run tool/l10n_merge.dart && flutter gen-l10n && (cd packages/rasq_design && flutter gen-l10n)`。
   `AppLocalizations.supportedLocales` に `en` が入り、設定の一覧・端末の言語の判定・Material の訳が自動でついてくる。
3. 同梱プラグイン・Central のコンソール・サーバーのメール / 通知の訳は、それぞれのリポジトリで(言語の値は上の約束どおり
   `Accept-Language` / ORGATE の `locale` / プラグインの `locale` で届く)。

## いまの残り

`dart run tool/l10n_audit.dart` の数(D-484 の時点、抽出済み = `lib/shell`・`lib/features/settings`・`packages/rasq_design`)は
docs/PHASE1_PLAN.md の D-484 に書いた。次は数の多い領域(`features/nodeprog` / `features/store` / `features/vc` /
`features/onboarding` / `features/rai`)から、部品を分けて並べて進める。
