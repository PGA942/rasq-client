### 第1条　申込みと役割

1. 開発者は、氏名または法人名、連絡先、権利を持つ商品、必要な税務・精算情報を正確に届け出ます。変更が生じた場合は更新します。運営者は必要な範囲で確認資料を求めることがあります。
2. プラグインごとの開発者名・サポート窓口はストア上に表示します。法令上の表示事項を除き、審査用の個人情報・非公開連絡先を公開しません。
3. 運営者が利用者への販売、代金の収納、購入履歴、返金受付を担当し、開発者が開発、正確な説明、保守、権利処理および技術的な問い合わせ対応を担当します。販売・精算条件の合意がない商品を有料販売しません。

### 第2条　権利と配信許諾

1. 開発者は、自ら制作した部分または適法な許諾を得た部分を提出し、ライセンス、著作権表示、配布に必要な通知、ソース提供義務、素材・フォント・モデル等の利用条件を明示します。第三者の権利を保有しているとの保証を、権利者の許諾確認なしに行ってはなりません。
2. 開発者は運営者に対して、審査、保存、配信、購入済み利用者への再提供、安全対策およびストア上の紹介に必要な範囲で、提出物と紹介素材を複製・公衆送信・形式変換する非独占的な権利を許諾します。内容の改変や別商品への転用を当然に許すものではありません。
3. 審査用ソースコードは一般利用者への配布に含めません。閲覧者は審査・安全対応に必要な運営担当者と契約上管理された処理受託者に限定します。外部のAI審査サービスを使用する場合は、提出前に送信先、国・地域、送信する範囲、保存期間、学習利用の有無を表示します。非公開ソースをAIモデルの学習や別商品の開発に使う許諾を、本条件に含めません。
4. 契約終了後も、既に取得した利用者の権利、購入履歴の証明、返金・紛争対応、法令上の保存に必要な範囲で許諾は存続します。新規の販売・配信は終了します。保存の具体的な期間と削除方法は開発者向けプライバシー説明に定めます。
5. SDK、サンプル、プラグイン、素材それぞれのライセンスは分けて表示します。再配布を禁止する場合は、禁止対象となる独自のファイル・素材、例外、利用者ができるバックアップ等を特定します。第三者ライセンスが与える改変・再配布の権利を禁止しません。

### 第3条　提出情報と安全条件

1. 各版について、配布物、バージョン、変更点、権限とその理由、通信先、取扱データ、保存期間、削除方法、サポート連絡先、利用許諾を提出します。審査のためにソースコードやビルド手順を求められた場合は、秘密情報を除いた確認可能な資料を提出します。
2. 認証情報・利用者データの不必要な取得、未申告の外部送信、同意前の権限利用、限定公開データの無断公開、課金や公開操作の偽装、審査回避、依存ライブラリの許諾違反を行ってはなりません。
3. 通信先や取扱データを広げる場合は、権限名が同じでも変更として申告し、新たな版で審査を受けます。掲載済みのバイナリや同一版の内容を、審査を経ずに差し替えることはできません。
4. 開発者鍵を管理し、漏えい・不正使用が疑われるときは直ちに運営者へ連絡して失効・交換します。署名は審査情報の正確さや安全性を免責するものではありません。
5. 脆弱性、権利侵害、データ事故が判明した場合は、［要確定: セキュリティ窓口］へ対象版、影響、対処予定を速やかに知らせ、被害抑止・利用者通知・修正版の配信に協力します。

### 第4条　審査と異議申立て

1. 審査では、決定的な検査、自動・AIによる評価、人による確認を組み合わせます。自動処理で承認する場合がありますが、自動評価で不明・否定的となったことだけを理由に最終的な掲載拒否を確定せず、人が再確認します。
2. 承認、差戻し、保留、停止について、対象の版、主な理由、修正や追加資料の要否を開発者へ通知します。被害拡大や検査回避に直結する情報、通報者・第三者の情報は、保護に必要な範囲で非開示とすることがあります。
3. 開発者は、［要確定: 開発者審査の問い合わせ・再審査窓口］へ根拠と資料を提出して異議を申し立てられます。運営者は人が再検討し、結果を通知します。アカウント制裁の解除申請と、商品の審査に対する異議申立ては区別して受け付けます。
4. 審査通過は、将来の継続掲載、全ての環境での動作、第三者の権利を侵害しないことを保証しません。審査後も申告と動作の不一致を調査する場合があります。

### 第4条の2　審査料

1. 掲載または新しい版の審査を申し込むときは、申込画面に表示する審査料を支払います。審査料の額は、申し込む版の配布物の大きさに応じて、申込画面に表示する計算方法で定めます。申込前に、金額（税込）とその計算の内訳、対象となる版と範囲、審査に含む確認（自動検査、AIを用いた評価、人による確認、差戻し後の再審査の回数）、結果通知までの目安、支払方法、取消しと返金の条件を表示します。支払はStripeを通じて行い、決済が完了し、申込みの受付を通知した時点で申込みが成立します。
2. 審査料は審査の作業に対する料金です。承認、掲載の継続、ストアでの表示順、利用者数や売上を保証するものではありません。審査の結果が差戻しまたは不承認になったことだけを理由とする返金は行いません。
3. 次の場合は、審査料の全額を返金します。(1) 審査に着手する前に開発者が申込みを取り消した場合。(2) 運営者が審査を引き受けないと判断した場合。(3) 結果通知の目安を【要確定: 30日】過ぎても運営者が審査に着手できず、開発者が取消しを求めた場合。(4) 二重決済、誤請求その他の決済の誤り。(5) 異議申立ての再検討で、運営者の誤りにより不承認としたことが確認された場合。
4. 差戻しを受けた版の修正版は、差戻しの通知から【要確定: 30日】以内の最初の再提出に限り、追加の審査料なしで再審査します。それ以外の再提出、別の版、内容を大きく変えた提出は、新しい申込みとして扱います。
5. 第4条第3項の異議申立てには料金がかかりません。審査料の支払の有無によって、審査基準、結果、通知する理由の詳しさを変えません。
6. 運営者は当面、少人数で審査を行います。結果通知の目安は申込画面に表示する目安であり、申込みが集中した場合は遅れることがあります。遅れる見込みのときは、申込者に知らせます。
7. 本条は、開発者が法令上持つ権利を制限するものではありません。

### 第5条　販売と精算

1. 有料商品の価格、税込み表示、対象となる更新範囲、運営者の手数料、精算対象額の計算、税の取扱い、精算日、振込手数料、最低精算額を、別紙販売条件で合意してから販売します。
2. 精算の基礎は、利用者が実際に購入に使用した対価とします。ポイントを購入した時点で、特定の開発者の売上として確定しません。無償ポイント、値引き、キャンペーン負担の配賦方法も別紙に明記します。
3. 精算書には、商品別売上、返金、取消し、決済費用、合意した手数料、税調整、繰越額を表示します。返金・不正利用に関して留保が必要な場合は、根拠、対象額、見直し時期を通知し、無関係な売上を無期限に留保しません。
4. 利用者への返金と開発者への精算調整は、原因と当事者の責任に応じて行います。運営者の決済障害や誤請求を、当然に開発者へ全額転嫁しません。開発者の虚偽申告や重大な不具合による合理的な返金は、合意した条件で調整できます。
5. 開発者は通知された精算内容について、［要確定: 精算照会窓口］へ確認を求められます。短い照会期間を設ける場合でも、計算誤りや法令上の請求権を一律に放棄させる条件にはしません。

### 第6条　掲載終了と責任

1. 開発者は、新規販売の終了を申請できます。既存利用者への再取得、サポート、返金、セキュリティ更新の取扱いを運営者と整理してから終了日を案内します。権利侵害や重大事故など緊急の場合は先に配信を停止できます。
2. 運営者は、違反や危険の内容に応じて、警告、特定版の停止、掲載終了、開発者権限の制限を行えます。可能な場合は事前に理由と是正の機会を示し、緊急停止後も異議申立てを受け付けます。
3. 掲載終了や契約終了だけを理由に、第三者ライセンスで許された利用・改変・再配布を禁止しません。既購入者に提供できなくなる機能があるときは、運営者と開発者が原因に応じて修正・代替・返金へ対応します。
4. 双方は、それぞれの責任により相手方または利用者へ与えた損害について、法令および個別に合意した条件に従って責任を負います。全ての紛争・第三者請求を一方へ無条件に負担させる補償条項は設けません。
