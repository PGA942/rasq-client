### 1. 運営者と適用範囲

［運営者の正式名称］（以下「運営者」）は、RASQのアプリ、RASQアカウント、ASTell、RAi、プラグインストアその他運営者が提供する機能において、次のとおり情報を取り扱います。

- 運営者：［個人・法人の正式名称］
- 所在地：［所在地］
- 法人の場合の代表者：［代表者名］
- 個人情報に関する窓口：［メールアドレスまたはフォームURL］
- 外部送信先・委託先一覧：［公開URL］

接続したSNS、第三者のプラグイン、利用者が指定した推論サーバーの運営者による取扱いには、それぞれのポリシーも適用されます。RASQからこれらへ何を送るかは、本書と各機能の確認画面で説明します。RASQサーバーの接続先を変更する場合は、その接続先の運営者とポリシーを確認してください。

### 2. 情報を扱う目的

運営者は、次の目的に必要な範囲で情報を取り扱います。

1. ログイン、本人確認、端末管理、設定の保存、利用者が選んだ連携・共有機能の提供。
2. 投稿・通話・共有・検索・補助機能とプラグインストアの提供。
3. 購入、利用権の付与、決済照合、返金、問い合わせ対応、会計・法令上必要な記録の管理。
4. 不正アクセス、規約違反、権利侵害への対応、異議申立ての審査、サービスの安全性確保。
5. 障害の検知・調査、性能・品質の維持。

私的な会話や限定公開の投稿を広告の出し分けに利用しません。モデルの回答・分類に情報を使う処理と、モデルの学習データとして蓄積する処理は区別します。学習へのデータ提供については第10項に定めます。

### 3. 端末内に保存する情報

ネイティブ版では、SNSのログイン情報、設定、下書き、RAiの会話履歴・実績、タイムラインのカスタマイズなどを端末に保存します。macOS版のSNSログイン情報はOSのKeychainを利用して保存します。

利用者が送信・同期を行う機能、サーバー処理を利用する機能、Web版のログイン情報保管庫では、次項以降に記載する情報が端末の外へ送られます。端末内にある情報すべてが、同じ暗号化方式・同じ保存先になるわけではありません。

端末内のデータは、アプリ内の履歴削除・ログアウト等により管理できます。アカウントの削除と、各端末のローカルデータ削除は別の操作です。OSのバックアップに含まれたデータは、そのバックアップの管理方法にも従います。

### 4. SNSの認証情報・アカウント連携

SNSのアクセストークンは、SNSでの操作を行うための認証情報です。RASQでは次の経路を区別します。

| 機能・利用条件 | 送信先と取扱い | 停止・解除 |
|---|---|---|
| 通常のSNS利用 | 選択したSNSへの投稿、閲覧、リアクション、フォロー等に必要な内容と認証情報を、そのSNSへ送ります | SNSのログアウト・連携解除。既にSNSへ送った投稿等はSNS側で管理します |
| Mastodonの認証仲介 | RASQサーバーが認証コードをSNSのトークンに交換し、認証結果とトークンをアプリへ返します。この認証仲介だけを理由に継続利用のためのトークン保管を行いません | 認証の中止・SNS側での連携解除。認証処理記録の期間は第9項に記載します |
| SNSログイン情報の端末間共有（任意） | 承認した端末同士で共有できるよう、端末で暗号化したログイン情報をRASQサーバーへ保存します。共有用の内容は承認端末の鍵で復号します | 「アカウントのセキュリティ」から共有停止・端末管理。停止前に別端末へ渡ったトークンがSNS側で自動失効することはありません |
| Web版のログイン情報保管庫 | RASQアカウントへログインしてWeb版でSNSを利用すると、ログイン情報をRASQサーバーの保管庫へ送り、必要時に読み戻します。保存時はサーバーの鍵で暗号化します。RASQサーバーが復号できる方式です | Web版のSNSログアウト、保管庫の削除、RASQアカウント削除。操作履歴の保持範囲は第9項に記載します |
| アカウントページへのSNS投稿表示（任意） | 確認画面で同意したSNSについて、RASQサーバーがアクセストークンを受け取り、保存時にサーバーの鍵で暗号化します。対象SNSから本人の表示対象投稿を取得し、RASQの公開アカウントページへ表示します | 投稿表示用の預託解除、SNS連携解除、RASQアカウント削除 |

投稿表示用の預託は、端末間共有やWeb版保管庫とは別の選択です。この機能では、選択したSNSの「公開」および「ホーム／未収載」に相当する投稿を、**RASQのアカウントページでは誰でも見られる状態**にします。フォロワー限定、指名・DM、ローカル限定、公開範囲を確認できない投稿は対象にしません。「ホーム／未収載」はフォロワー限定という意味ではありません。

投稿表示のために預かったトークンを、投稿・フォロー等の書き込み操作や、別の目的のために利用しません。別機能でフォロー関係を確認する場合は、対象SNS・目的・送る内容を示して別途選択できるようにします。

アカウントの束ね表示には、連携するSNSの種類、サーバー、アカウント識別子、表示情報、確認結果を使用します。公開する範囲はプロフィールの設定に従います。

### 5. RASQサーバーに保存する主な情報

| 情報 | 利用目的・表示範囲 |
|---|---|
| ハンドル、表示名、画像、自己紹介、投稿、公開設定、連携アカウント | アカウント・プロフィール・投稿機能の提供。公開設定に応じて他の利用者へ表示 |
| ログイン用の認証情報、確認済みメール、端末識別子・名称、ログイン日時、IPアドレス、User-Agent | 認証、アカウント保護、端末一覧、通知、本人確認 |
| 同意の種類・文書版・日時・年齢帯・保護者同意の記録 | 利用条件・選択内容の確認、機能制限、問い合わせ対応 |
| 同期を選択した設定、プラグイン導入情報、カスタマイズ、共有用データ | 保存・復元・端末間の共有。暗号化方式は機能ごとに示します |
| リスト・クリップ等の保存内容、ブックマーク、ストアのレビュー | 機能提供と、選択した公開範囲での表示 |
| 商品・注文の識別子、価格・通貨、購入日時、支払状態、決済事業者の取引識別子、ポイント付与・利用・失効、利用権、返金・取消・問い合わせ記録 | 代金処理、二重付与防止、購入の復元、返金、会計、不正利用防止 |
| 通報・異議申立て、関連する発信・共有内容、対応結果 | 規約違反・権利侵害・安全上の問題の調査と再審査 |
| 通知用識別子・通知設定・通知内容 | 利用者が有効にした通知の配信 |

有料機能は、プラグインの買い切り・サブスクリプション、ASTellおよびプラグインプロキシのサブスクリプションを対象とし、ポイント払いを主に利用します。決済事業者にはStripeを利用します。注文・支払・ポイント利用に加え、定期契約の開始・更新・解約・利用権、返金・取消・紛争に関する記録を取り扱います。決済情報の入力先、Stripeから運営者が受領する情報は、購入前の画面と外部送信先一覧に示します。［正式Stripe連携で、カード番号等を運営者が受け取るかどうかを確定して記載］。

### 6. ASTell、RAi、プラグイン

**ASTell：** ルーム情報、参加情報、共有した投稿・テキスト・ファイル、文字起こし等を、選択した機能の提供に用います。音声・映像の接続先、文字起こしの送信先、参加者に見える範囲はASTellの説明で示します。字幕表示をオフにする操作と、文字起こし用の送信・処理を止める操作は区別します。安全管理・通報の調査のため、権限を持つ運営担当者が必要な範囲の共有内容等を確認する場合があります。

**RAi：** 端末内モデルの処理、回答用の推論サーバー、検索用の埋め込みサーバー、Web検索はそれぞれ別の送信経路です。外部処理を使う場合は、送信先・目的・対象データを事前に示します。質問、操作リファレンス、回答に必要な取得結果などが処理対象になることがあります。端末内モデルが利用できない場合に外部へ切り替えるかどうかも利用者が確認できるようにします。外部への送信を許可しない場合、端末内で使える範囲の機能を利用できます。

**プラグイン：** プラグインが利用する情報と外部通信は、権限の説明と開発者のポリシーで確認できます。RASQ運営者が提供する機能の取扱いと、プラグイン開発者の取扱いを分けて表示します。プラグインを削除しても、既に開発者のサーバーへ送った情報が同時に消えるとは限りません。削除方法は各ポリシーに従います。

### 7. 通報・安全管理・自動処理

通報や異議申立てへの対応では、対象の発信、関連する時刻・ルーム・アカウント情報、通報の前後の文脈、過去の対応結果を確認する場合があります。処理の補助に、文章・画像の分類、発信傾向の分析、対応案の生成を用いる場合があります。これはサービスの安全管理を目的とする推論処理であり、第10項の任意の学習用データ提供とは区別します。

これらの情報を扱える者を担当業務上必要な者に限定します。委託先へ処理を委ねる場合は、委託先・送信する情報・保存期間等を一覧で示します。自動処理の役割と、利用制限に対する理由の確認・異議申立ての方法は、利用規約と安全管理の説明に定めます。

### 8. 外部サービス・国外での取扱い・安全管理

運営者は、ホスティング、配信、メール、通話、決済、広告、推論等のために外部サービスを利用する場合があります。実際に利用する事業者名、送信する情報、目的、処理・保存する国または地域、保存期間、各ポリシーへのリンクを［外部送信先・委託先一覧］に掲載します。

送信先を「国内のみ」と一括して説明せず、実際の構成に合わせて示します。利用者が指定したSNSや推論サーバーについては、その管理者の取扱いも確認してください。

運営者は、情報に応じたアクセス制限、通信の保護、認証情報の保護、担当者・委託先の管理、削除の管理等を行います。暗号化して保存する情報でも、運営者の鍵で復号するものと利用者の端末でのみ復号するものを区別します。法令上認められる場合等を除き、本人の同意を得ずに個人データを第三者へ提供しません。

### 9. 保存期間と削除

情報は目的に必要な期間に限り保存し、期間の終了または有効な削除請求により削除するか、個人を識別できない状態にします。匿名化と呼ぶ場合は、識別子を置き換えるだけの処理と区別します。

| 区分 | 保存の終期・解除方法 |
|---|---|
| 通常のアカウント・連携・同期データ | 利用中に必要な期間。個別の解除・削除またはRASQアカウント削除により削除を開始 |
| 投稿表示用トークン・取得投稿 | 預託解除またはSNS連携解除により利用停止・削除。処理中の取得・キャッシュ・バックアップを含む完了期限：［確定日数］ |
| Web版保管庫・端末間共有 | ログアウト・共有停止等による削除範囲を確認画面へ表示。操作履歴・削除情報の保持期限：［確定日数］ |
| ASTellの共有・文字起こし・アップロード | 参加者向け表示は作成から10日間、通常の内部保管は作成から30日間。削除処理の完了期限：［ジョブ間隔を含む確定期限］。個別の保全が必要な情報は下記の例外に従う |
| 閉じたASTellルームの記録 | 閉鎖から30日を通常の保持期間とする。共有・文字起こし・アップロードの期限を、ルーム閉鎖日によって延長しない |
| 認証の一時処理、ログイン試行、運用ログ | ［認証状態・ログ種別ごとの確定期間］ |
| 通報・異議申立て・対応記録 | ［終結時からの確定期間］。係争等で延長する場合は必要範囲・終了条件を管理 |
| 契約・決済・返金・会計記録 | ［適用法令と業務上必要な期間を確定］。通常のアカウント情報から分離し、購入・定期更新・返金・紛争・会計等の目的に限って使用 |
| 削除記録・凍結回避防止情報 | ［それぞれの確定期間］。後者は必要な場合のハンドル・理由・端末識別子のハッシュ等、必要最小限 |
| バックアップ | ［最長失効期間］。復元時にも削除・撤回の状態を反映 |

RASQアカウントの削除は、アプリのアカウント管理または［削除手続きURL］から行えます。アプリへ入れない場合は窓口へ連絡してください。削除時は、アカウントに結び付いた通常データの利用を停止し、削除処理を行います。決済・返金・法令対応、係争中の権利保護、不正利用防止に必要な最小限の情報は、上表の範囲で分離して保持することがあります。

他の利用者が記録・再共有した情報、接続先SNSのアカウント・投稿、利用者の端末やバックアップは、RASQアカウントの削除だけでは消えません。RASQ側の削除処理は、各SNSのアカウントや投稿を削除する操作ではありません。

### 10. 学習へのデータ提供

**正式版の開始時点では、学習へのデータ提供の受付を閉じています。** RASQの利用、ASTellの利用、RAiの利用、プラグインの購入を、任意の学習用データ提供への同意として扱いません。

受付を開始する場合は、対象データ、目的、保存期間、モデルへの反映・配布、撤回後の対応を別の文書で示し、改めて選択を求めます。既定は「提供しない」とし、拒否・撤回によって通常の機能や有料機能の利用条件を不利に変更しません。

開始を検討している対象は、16歳以上の本人が自分で書いた公開投稿と、条件を満たす投稿間の関連判定ラベルです。16～17歳の場合は保護者の同意も必要です。他人が拒否表示をしていないことや、AIによる許可判定を、その人の同意の代わりにはしません。DM、限定公開投稿、ASTellの会話、RAiの質問・回答履歴をこの選択に含めません。将来これらを対象にする場合も、別の設計・文書・選択が必要です。

### 11. 年齢、本人の権利、変更

RASQの利用は13歳以上を対象とし、未成年者は保護者の同意を得て利用してください。これはRASQの利用条件です。年齢帯・保護者同意等の確認に必要な情報を取り扱います。追加の本人確認を行う場合は、取得する情報・事業者・保存期間を取得前に説明します。

保有する個人データの開示、訂正、利用停止・消去、第三者提供の停止等については、窓口へ請求できます。本人確認の方法、必要書類、手数料がある場合の額、対応手順は［請求手続きURL］に示します。法令に基づき対応できない場合は、その理由を説明します。

取扱いを変更する場合は、変更内容と適用日を通知します。利用目的や任意の送信範囲を拡大する場合など、改めて同意・選択が必要な変更は、変更前に確認します。過去の文書版も確認できるようにします。
