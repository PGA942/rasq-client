### 第1條　申請與角色

1. 開發者應正確申報姓名或法人名稱、聯絡方式、擁有權利之商品，以及必要之稅務、結算資訊。發生變更時應予以更新。營運者得於必要範圍內要求提供確認資料。
2. 各外掛之開發者名稱及支援窗口，顯示於商店上。除法令上之應標示事項外，不公開審查用之個人資料及非公開聯絡方式。
3. 由營運者負責對使用者之銷售、價款之收取、購買紀錄及退款受理；由開發者負責開發、正確說明、維護、權利處理及技術性詢問之回應。未就銷售、結算條件達成合意之商品，不以付費方式銷售。

### 第2條　權利與發布授權

1. 開發者應提交自行製作之部分或已取得合法授權之部分，並明示授權條款、著作權標示、散布所需之通知、提供原始碼之義務，以及素材、字型、模型等之使用條件。未經確認權利人之授權，不得保證擁有第三人之權利。
2. 開發者授予營運者於審查、保存、發布、對已購買使用者之重新提供、安全對策及於商店上介紹之必要範圍內，重製、公開傳輸及轉換格式提交物與介紹素材之非專屬權利。此授權並非當然允許修改內容或轉用於其他商品。
3. 審查用原始碼不包含於對一般使用者之散布中。閱覽者限於審查、安全處理所必要之營運人員，以及依契約受管理之受託處理者。使用外部AI審查服務時，於提交前顯示傳送對象、國家、地區、傳送範圍、保存期間及是否用於學習。本條件不包含將非公開原始碼用於AI模型之學習或開發其他商品之授權。
4. 契約終止後，於已取得之使用者權利、購買紀錄之證明、退款、紛爭處理及法令上之保存所必要之範圍內，授權繼續存續。新的銷售、發布則予以終止。保存之具體期間及刪除方式，規定於第7條。
5. SDK、範例、外掛、素材各自之授權條款，分別標示。禁止再散布時，應特定禁止對象之獨有檔案、素材、例外情形，以及使用者得進行之備份等。不禁止第三方授權條款所賦予之修改、再散布之權利。

### 第3條　提交資訊與安全條件

1. 就各版本，提交散布物、版本、變更內容、權限及其理由、通訊對象、處理之資料、保存期間、刪除方式、支援聯絡方式及使用授權。為審查而被要求提供原始碼或建置程序時，應提交除機密資訊外可供確認之資料。
2. 不得不必要地取得驗證資訊、使用者資料、進行未申報之外部傳送、於同意前使用權限、擅自公開限定公開之資料、偽裝付費或公開操作、規避審查，或違反相依函式庫之授權。
3. 擴大通訊對象或處理之資料時，即使權限名稱相同，亦應作為變更申報，並以新版本接受審查。不得未經審查而替換已上架之二進位檔或同一版本之內容。
4. 開發者應管理開發者金鑰，懷疑有外洩或不當使用時，應立即聯絡營運者並進行撤銷、更換。簽章並不免除審查資訊之正確性或安全性之責任。
5. 發現漏洞、權利侵害或資料事故時，應迅速向［待定：資安窗口］告知相關版本、影響及處理預定，並協助防止損害、通知使用者及發布修正版本。

### 第4條　審查與申訴

1. 審查結合確定性檢查、自動、AI評估及人員確認。雖可能以自動處理予以核准，但不會僅以自動評估結果為不明或否定為由確定最終拒絕上架，而由人員重新確認。
2. 就核准、退回、保留、停止，將相關版本、主要理由及是否需要修正或補充資料通知開發者。與損害擴大或規避檢查直接相關之資訊、檢舉人、第三人之資訊，得於保護所需之範圍內不予揭露。
3. 開發者得向［待定：開發者審查之詢問、重新審查窗口］提交依據及資料以提出申訴。營運者將由人員重新檢討，並通知結果。帳號處分之解除申請與對商品審查之申訴，分別受理。
4. 通過審查並不保證未來繼續上架、於所有環境中均可運作，或不侵害第三人之權利。審查後，仍可能調查申報內容與實際運作之不一致。

### 第4條之二　審查費

1. 申請上架或新版本之審查時，應支付申請畫面所顯示之審查費。審查費之金額，係依營運者公開之計測方式（包含計測所使用之詞彙及其版本），計算所申請版本之散布物中所含檔案內容之片段（piece）數，並以申請畫面所顯示之計算公式決定。散布物之位元組數僅為參考，即使大小相同，金額亦因內容而異。開發者可於申請前，透過營運者提供之計測工具確認相同之片段數及金額。申請前，將顯示金額（含稅）及其計算明細（片段數、計測方式及計算公式）、相關版本及範圍、審查所包含之確認（自動檢查、使用AI之評估、人員確認、退回後重新審查之次數）、開始審查及通知結果之預估時間、付款方式，以及取消與退款之條件。付款透過Stripe進行，於付款完成並通知受理申請之時點，申請即告成立。
2. 審查費係對審查作業之費用。不保證核准、繼續上架、於商店中之顯示順序、使用者人數或營業額。不會僅以審查結果為退回或不核准為由退款。
3. 有下列情形之一者，全額退還審查費。(1) 開發者於開始審查前取消申請時。(2) 營運者判斷不受理審查時。(3) 自受理申請起已逾第7項之開始審查預估時間，營運者仍未開始審查，而開發者取消申請時。(4) 自開始審查起已逾第7項之結果通知預估時間，營運者仍未通知結果（核准、退回或不核准），而開發者於結果通知前取消申請時。(5) 重複付款、錯誤請款或其他付款錯誤。(6) 於申訴之重新檢討中，確認係因營運者之錯誤而不核准或退回時。
4. 已支付審查費之申請遭退回時，開發者於退回通知後【待定：30日】內，指定遭退回之申請，並提交同一外掛之版本作為該退回之修正者，僅限第一次，不另收審查費而進行重新審查。不另收審查費而重新審查之申請再次遭退回時，不適用此處理。未指定遭退回之申請之提交、逾期之提交、一般更新或其他外掛之提交，均視為新申請而收取審查費。
5. 第4條第3項之申訴不收取費用。不因是否支付審查費而改變審查基準、結果或所通知理由之詳細程度。
6. 營運者目前以少數人員進行審查。於申請集中等情形，可能無法於第7項之預估時間前開始審查或通知結果。預期如此時，將於預估日期前，告知申請人預計延遲及新的預估日期。此告知不改變第7項之預估時間及第3項之退款條件。
7. 本條所稱「開始審查」，係指營運者已開始該版本之審查（已執行自動檢查，且審查負責人已記錄開始），營運者於開始審查時通知申請人。開始審查之預估時間為自受理申請起【待定：30日】內，結果通知之預估時間為自開始審查起【待定：30日】內，並於申請畫面顯示各自之日期。
8. 本條不限制開發者依法令所享有之權利。

### 第5條　銷售與結算

1. 有償商品之價格、含稅標示、適用之更新範圍、營運者之手續費、結算對象金額之計算、稅務處理、結算日、匯款手續費及最低結算金額，於另附之銷售條件中達成合意後始進行銷售。
2. 結算之基礎，為使用者實際用於購買之對價。購買點數之時點，不確定為特定開發者之營業額。免費點數、折扣、促銷活動負擔之分配方式，亦於附件中明定。
3. 結算單中顯示各商品之營業額、退款、取消、付款費用、合意之手續費、稅額調整及結轉金額。就退款、不當使用有保留之必要時，將通知依據、相關金額及重新檢視時期，不會無限期保留無關之營業額。
4. 對使用者之退款及對開發者之結算調整，依原因及當事人之責任進行。營運者之付款故障或錯誤請款，不當然全額轉嫁予開發者。因開發者之虛偽申報或重大缺陷所致之合理退款，得依合意之條件調整。
5. 開發者得就所通知之結算內容，向［待定：結算查詢窗口］要求確認。即使設有較短之查詢期間，亦不會設定使開發者一律放棄計算錯誤或法令上請求權之條件。

### 第6條　下架與責任

1. 開發者得申請終止新的銷售。將與營運者整理對既有使用者之重新取得、支援、退款及安全性更新之處理後，再告知終止日期。於權利侵害或重大事故等緊急情形，得先停止發布。
2. 營運者得依違規或危險之內容，進行警告、停止特定版本、下架或限制開發者權限。於可能時，將事先標示理由並提供改正機會，緊急停止後亦受理申訴。
3. 不會僅以下架或契約終止為由，禁止第三方授權條款所允許之使用、修改、再散布。有無法再提供予既有購買者之功能時，營運者與開發者將依原因進行修正、替代、退款之處理。
4. 雙方就各自之責任對相對人或使用者所造成之損害，依法令及個別合意之條件負責。不設置使一方無條件承擔所有紛爭、第三人請求之補償條款。

### 第7條　開發者資訊之處理

1. 營運者為審查、發布、結算、安全處理、詢問回應之目的，處理開發者之申請內容、聯絡方式、開發者金鑰之公鑰、用於復原簽章之備註、所提交之散布物及原始碼、審查紀錄及審查費之付款紀錄。本條未規定之事項，依隱私權政策。
2. 審查中，除確定性檢查外，亦使用營運者管理之判定系統及外部AI。向外部AI傳送所提交之散布物及原始碼。目前之傳送對象為 OpenAI（Codex，美國）。亦使用於營運者電腦上執行之 Alibaba 的 Qwen 模型，惟此模型之處理不會傳送至外部。將透過與傳送對象之契約，確認不將所傳送之內容用於AI學習之條件。變更傳送對象時，將於申請前顯示。
3. 提交審查之原始碼，不散布予使用者。上架期間，為重新審查及安全處理而保存，並於下架後1年內刪除。
4. 審查費之付款紀錄，自交易年度結束起保存8年。刪除開發者帳號後，將替換為不與帳號連結之識別碼，並刪除申請備註等自由記述後保存。
5. 何時審查何版本及其結果之紀錄，為使用者之安全及紛爭處理，於下架後亦予保存。審查負責人及開發者之帳號，於帳號刪除後自紀錄中分離。
6. 即使刪除開發者帳號，已上架之外掛於經第6條之程序前仍保留於商店中。開發者之顯示將替換為刪除後之顯示。
